# 认证与请求上下文规范

本文档约束用户登录态、服务端 session、当前用户解析和请求上下文使用方式。

## 认证模式

- 用户登录态默认使用 Litestar `SessionAuth`。
- session 数据默认保存在 Redis；memory store 只用于本地或测试场景。
- cookie 只保存 session id；session 只保存最小身份信息，默认使用 `user_id`。
- 当前用户对象统一使用领域 schema，不向 controller 暴露数据库模型。
- 系统级接口统一使用 `/system` 前缀，并在认证排除规则中按前缀忽略。

## 生命周期

- session 过期时间由认证配置控制，并同步作用于 cookie 与 Redis TTL。
- 需要滑动过期时，通过 session 配置开启访问续期。
- 登出必须清理服务端 session，不只删除前端本地状态。
- 用户被禁用、删除或 session 数据异常时，应视为未认证。

## 请求上下文

- 业务接口需要请求上下文时，默认注入 `ctx: RequestContext`。
- `RequestContext` 定义在 `src/aigc/shared/context.py`，由 `request.user` 和 `request.session` 构建。
- 业务代码不直接解析 cookie 和 session。
- cookie 不作为业务身份来源，身份解析以认证中间件和 session 数据为准。
- 未登录上下文可以存在；是否拒绝请求由认证、guard 或 controller 按接口要求处理。

## 注册方式

- `RequestContext` provider 通过 `server.plugin` 注册为全局依赖。
- 认证中间件、Redis Store、session backend 等运行时能力通过 `server.plugin` 装配。
- controller 不直接注册全局依赖，不直接修改应用级认证配置。

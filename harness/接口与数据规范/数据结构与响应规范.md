# 数据结构与响应规范

本文档约束数据结构、请求响应、分页和 Pydantic 模型的使用边界。ORM 细节以《ORM 与数据模型规范》为准。

## 默认选择

- 普通数据结构默认继承 `BaseStruct`。
- HTTP 请求参数和对外响应字段默认继承 `CamelizedBaseStruct`。
- 请求响应默认使用 `GenericResponse`。
- 分页响应默认使用 `GenericResponse[Pagination]`。
- 数据库持久化模型默认继承 `CustomModel`，具体规则见《ORM 与数据模型规范》。
- `pydantic.BaseModel` 不是默认选择，只在确有收益或外部依赖要求时使用。

## 命名约定

- 数据库模型：`UserModel`。
- 服务层数据结构：`UserStruct`。
- 创建入参：`UserCreate`。
- 更新入参：`UserUpdate`。
- 对外展示对象：`UserVO`。
- 服务类：`UserService`。

同一实体应按创建、更新、服务层传递、对外展示、数据库持久化拆分 schema。

## 请求与服务层结构

- 请求体和查询参数 schema 默认继承 `CamelizedBaseStruct`。
- 路径参数名称与路由占位符保持一致，仍使用小写蛇形命名。
- 对外 HTTP 字段默认使用驼峰命名，用于接收前端传入参数和返回响应。
- 创建入参不携带 `id`、`created_at`、`updated_at` 等数据库维护字段。
- 更新入参应明确区分“不更新”和“更新为空”的语义。
- 服务层传递对象使用 `BaseStruct`，不依赖 HTTP 响应结构。
- service 不向 controller 返回数据库模型。

## 对外展示与响应

- API 对外展示对象使用 `VO` 后缀，并继承 `CamelizedBaseStruct`。
- VO 不直接复用数据库模型。
- VO 不暴露密码、令牌、连接串、内部状态、软删除标记等敏感字段。
- 返回单个对象使用 `GenericResponse[UserVO]`。
- 返回非分页列表使用 `GenericResponse[list[UserVO]]`。
- 返回分页数据使用 `GenericResponse[Pagination]`。
- 错误响应交给统一异常处理层转换。

## 分页结构

- `Pagination.data` 固定为当前页数据列表。
- `Pagination.length` 是当前页实际返回条数。
- `Pagination.next_offset` 是下一页偏移量。
- 即使没有下一页，`next_offset` 也保持 `int`，返回 `offset + length`。
- `Pagination.total` 可为 `None`。
- 默认不强制查询总数；只有前端明确需要总页数或总量时才查询准确 `total`。

## Pydantic 边界

允许使用 `pydantic.BaseModel` 的场景：

- 第三方依赖明确要求。
- 框架集成边界必须使用。
- 复杂校验、字段约束或生态复用收益明确。

使用 Pydantic 时，应与 `BaseStruct` 系列显式转换，不把 Pydantic 作为默认 schema 基类。

## 时间字段

- 时间字段统一使用 timezone-aware `datetime`。
- 对外输出时间不得丢失时区信息。
- 测试中构造时间也应使用带时区的固定值。

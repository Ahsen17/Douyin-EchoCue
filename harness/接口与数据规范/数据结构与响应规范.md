# 数据结构与响应规范

本文档约束 schema、结构转换、响应包装、分页和 Pydantic 使用边界。ORM 细节以《ORM 与数据模型规范》为准。

## 默认选择

- 普通数据结构默认继承 `BaseStruct`。
- HTTP 请求参数和对外响应字段默认继承 `CamelizedBaseStruct`。
- 请求响应默认使用 `GenericResponse`。
- 分页响应默认使用 `GenericResponse[Pagination]`。
- 数据库持久化模型遵守《ORM 与数据模型规范》。
- `pydantic.BaseModel` 不是默认选择，只在确有收益或外部依赖要求时使用。

## 命名约定

- 服务层数据结构：`UserStruct`。
- 创建入参：`UserCreate`。
- 更新入参：`UserUpdate`。
- 对外展示对象：`UserVO`。

同一实体应按创建、更新、服务层传递和对外展示拆分 schema。

## 请求与服务层结构

- 请求体和查询参数 schema 默认继承 `CamelizedBaseStruct`。
- 路径参数名称与路由占位符保持一致，仍使用小写蛇形命名。
- 对外 HTTP 字段默认使用驼峰命名。
- 创建入参不携带 `id`、`created_at`、`updated_at` 等数据库维护字段。
- 更新入参应明确区分“不更新”和“更新为空”的语义。
- 服务层传递对象使用 `BaseStruct`，不依赖 HTTP 响应结构。
- schema 只表达数据形状、边界转换和命名映射，不承载业务流程或额外字段值校验。
- 字段类型本身可表达的约束优先交给类型系统、msgspec 和 Ruff；确需表达字段级约束时优先使用 `Annotated` 等类型化方式。
- 不在 schema 中手写与业务规则相关的 `__post_init__` 校验；业务规则放入 handler、service 或领域逻辑模块。

## 结构转换

- `BaseStruct`、`CamelizedBaseStruct` 和其他 msgspec 结构之间转换时，优先使用 msgspec 提供的能力，例如 `msgspec.convert`、`msgspec.to_builtins`、`msgspec.structs.asdict` 和 `msgspec.structs.fields`。
- 避免在 `to_struct()`、`from_struct()` 等转换方法中逐字段手写赋值。
- 当需要跨结构类型、嵌套结构或 camelCase / snake_case 边界转换时，应抽取小型通用转换 helper，而不是在每个 schema 中重复映射。
- schema 转换 helper 只处理结构转换，不承载业务校验、数据补全或副作用。

## 对外展示与响应

- API 对外展示对象使用 `VO` 后缀，并继承 `CamelizedBaseStruct`。
- VO 不直接复用数据库模型。
- VO 不暴露密码、令牌、连接串、内部状态、软删除标记等敏感字段。
- 返回单个对象使用 `GenericResponse[UserVO]`。
- 返回非分页列表使用 `GenericResponse[list[UserVO]]`。
- 返回分页数据使用 `GenericResponse[Pagination]`。
- 错误响应交给统一异常处理层转换。

## 分页结构

- `Pagination.data` 固定为当前页数据列表。
- `Pagination.length` 是当前页实际返回条数。
- `Pagination.next_offset` 是下一页偏移量。
- 即使没有下一页，`next_offset` 也保持 `int`，返回 `offset + length`。
- `Pagination.total` 可为 `None`。
- 默认不强制查询总数；只有前端明确需要总页数或总量时才查询准确 `total`。

## Pydantic 边界

允许使用 `pydantic.BaseModel` 的场景：

- 第三方依赖明确要求。
- 框架集成边界必须使用。
- 复杂校验、字段约束或生态复用收益明确。

使用 Pydantic 时，应与 `BaseStruct` 系列显式转换，不把 Pydantic 作为默认 schema 基类。

## 时间字段

- 时间字段统一使用 timezone-aware `datetime`。
- 对外输出时间不得丢失时区信息。
- 测试中构造时间也应使用带时区的固定值。

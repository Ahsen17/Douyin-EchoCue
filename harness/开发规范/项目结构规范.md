# 项目结构规范

本文档约束目录职责、模块落位和导入边界。新增代码先判断职责，再放入对应目录；不能明确归属时，先补清领域边界，不放入宽泛的 `utils`。

## 目录职责

- `src/aigc/base`：项目基础能力，包括配置、基础 schema、常量。
- `src/aigc/shared`：跨领域共享能力，包括响应、分页、数据库基础服务、项目级抽象。
- `src/aigc/server`：应用装配，包括 Litestar 配置、插件、日志、OpenAPI 配置。
- `src/aigc/controller`：HTTP 控制器，只处理路由、参数和响应，并通过 `controllers` 聚合导出。
- `src/aigc/core`：业务领域代码，包括领域 schema、model、service、repository。
- `src/aigc/lib`：与业务无关的轻量纯工具。
- `src/aigc/db`：数据库迁移、夹具和数据库资源。
- `tests`：自动化测试。
- `docs`：产品、架构和交付文档。
- `harness`：工程规范和协作约束。

## 落位规则

- 单领域专用代码放入 `src/aigc/core/<领域>`。
- 多领域复用且包含业务语义的代码放入 `src/aigc/core` 下的共享领域模块。
- 多领域复用且不含业务语义的项目能力放入 `src/aigc/shared`。
- 请求上下文等跨业务接口共享的运行时结构放入 `src/aigc/shared`。
- 不依赖项目配置、框架、数据库和业务语义的纯工具放入 `src/aigc/lib`。
- HTTP 接口放入 `src/aigc/controller`。
- 应用启动、插件、路由装配放入 `src/aigc/server`。
- server 插件通过 `plugins` 聚合，controller 通过 `controllers` 聚合。
- 基于依赖注入的全局能力扩展默认放入 `src/aigc/server/plugin`。
- 配置结构放入 `src/aigc/base/config`，并挂载到 `Config`。
- 数据库迁移放入 `src/aigc/db/migrations`。
- 测试辅助代码放入 `tests`，不得被生产代码导入。
- 测试目录按 `src/aigc` 下被测模块层级镜像组织。

## 领域模块

新增业务领域优先使用以下结构：

```text
src/aigc/core/<领域>/
  __init__.py
  schema.py
  model.py
  service.py
  repository.py
```

- `schema.py`：请求入参、服务层结构、对外 VO。
- `model.py`：数据库模型。
- `service.py`：业务流程、规则判断、数据转换、事务边界。
- `repository.py`：复杂查询封装；简单 CRUD 不强制新增。
- `__init__.py`：只导出稳定 API。

## 分层边界

- controller 不直接读写数据库，不承载复杂业务规则。
- controller 调用 service，并返回 `GenericResponse` 系列响应。
- service 不返回数据库模型给 controller。
- model 只表达数据库表结构和持久化能力。
- schema 只表达数据形状，不承载业务流程。
- shared 不依赖具体业务领域。
- base 不依赖 `controller`、`server`、`core`。
- server 负责装配 `controllers`、`plugins`、日志、中间件和 OpenAPI。

## 导入方向

推荐导入方向：

```text
controller -> core -> shared -> base
server -> controller/shared/base
core -> shared/base
base -> 标准库或第三方依赖
```

禁止生产代码导入测试代码。出现循环导入时，优先调整职责或把类型移动到 `schema.py`。

# 项目结构规范

本文档约束目录职责、模块落位、分层边界和导入方向。具体代码风格、数据结构、命令和测试规则分别由对应专题规范约束。

## 目录职责

- `src/aigc/base`：项目基础能力，包括配置、基础 schema、常量。
- `src/aigc/shared`：跨领域共享能力，包括响应、分页、数据库基础服务、上下文、异常和项目级抽象。
- `src/aigc/server`：应用装配，包括 Litestar 配置、插件、中间件、日志和 OpenAPI 配置。
- `src/aigc/controller`：HTTP 控制器，只处理路由、参数和响应，并通过 `controllers` 聚合导出。
- `src/aigc/core`：业务领域代码，包括领域 schema、model、service、repository、handler 和 enum。
- `src/aigc/lib`：与业务无关的轻量纯工具。
- `src/aigc/db`：数据库迁移、夹具和数据库资源。
- `tests`：自动化测试。
- `docs`：产品、架构和交付文档。
- `harness`、`harness_en`：工程规范和协作约束。

## 落位规则

- 单领域业务代码放入 `src/aigc/core/<领域>`。
- 多领域复用且包含业务语义的代码放入 `src/aigc/core` 下清晰命名的领域模块。
- 多领域复用且不含业务语义的项目能力放入 `src/aigc/shared`。
- 请求上下文、响应包装、基础数据库服务和项目级异常放入 `src/aigc/shared`。
- 不依赖项目配置、框架、数据库和业务语义的纯工具放入 `src/aigc/lib`。
- HTTP 接口放入 `src/aigc/controller`。
- 应用启动、插件、路由装配放入 `src/aigc/server`。
- server 插件通过 `plugins` 聚合，controller 通过 `controllers` 聚合。
- 基于依赖注入的全局能力扩展默认放入 `src/aigc/server/plugin`。
- 配置结构放入 `src/aigc/base/config`，并挂载到 `Config`。
- 数据库迁移放入 `src/aigc/db/migrations`。
- 测试代码放入 `tests`；测试组织细节遵守《测试规范》。

## 领域模块

新增业务领域按需要组合以下模块：

```text
src/aigc/core/<领域>/
  __init__.py
  schema.py
  enum.py
  model.py
  service.py
  repository.py
  handler.py
```

- `schema.py`：领域数据结构、请求入参、对外 VO 和结构转换边界。
- `enum.py`：领域枚举。
- `model.py`：数据库模型。
- `service.py`：ORM/database service，绑定模型、仓储和事务边界。
- `repository.py`：复杂查询封装；简单 CRUD 不强制新增。
- `handler.py`：业务流程编排、规则判断、外部能力协调和内存状态流转。
- `__init__.py`：稳定 API 聚合导出。

领域目录按业务概念聚合，不按技术过程拆成多个 `core` 顶层目录。属于同一业务域的事件、窗口、分类、解析等能力，应留在同一领域目录内，用职责清晰的模块拆分。

只有存在数据库模型、仓储或事务边界时才新增 `service.py`。不涉及 ORM/database service 语义的业务编排使用 `handler.py` 或更具体的模块名。

## 分层边界

- controller 不直接读写数据库，不承载复杂业务规则。
- controller 调用领域边界，并返回 `GenericResponse` 系列响应。
- service 不返回数据库模型给 controller。
- handler 不承担 ORM/database service 职责；需要数据库访问时通过 service 或 repository 边界完成。
- model 只表达数据库表结构和持久化能力。
- schema 只表达数据形状、命名映射和结构转换边界，不承载业务流程。
- shared 不依赖具体业务领域。
- base 不依赖 `controller`、`server`、`core`。
- server 负责装配 `controllers`、`plugins`、日志、中间件和 OpenAPI。

## 导入方向

推荐导入方向：

```text
controller -> core -> shared -> base
server -> controller/shared/base
core -> shared/base
base -> 标准库或第三方依赖
```

禁止生产代码导入测试代码。出现循环导入时，优先调整职责或把类型移动到 `schema.py`。

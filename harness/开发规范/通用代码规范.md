# 通用代码规范

本文档约束通用代码实现。目录落位、命令入口、测试范围和数据结构细节由对应专题规范约束。

## 基础约定

- Python 版本不低于 3.12。
- 项目采用 `src` 布局，核心包名为 `aigc`。
- 工具配置以 `pyproject.toml`、`Makefile` 和实际校验结果为准。
- 依赖管理使用 `uv`，依赖归类遵守项目配置。
- 不提交虚拟环境、缓存、构建产物、密钥和本地配置。

## 代码风格

- 使用 Ruff 格式化和检查。
- 行宽上限为 120。
- 使用空格缩进和 LF 换行。
- 导入顺序交给 Ruff 管理。
- 同级模块导入使用相对路径，例如 `from .schema import UserStruct`。
- 跨目录导入使用 `aigc` 绝对路径。
- 禁止父级相对导入，例如 `from ..xx import ...`。
- 变量、函数、模块使用小写蛇形命名。
- 类名使用大驼峰命名。
- 常量使用大写蛇形命名。
- `__all__` 只导出类类型。
- 函数、变量、实例和集合不写入 `__all__`。
- 使用非类成员时，从其定义模块原始路径导入。
- 注释只解释原因、约束或非显然行为。
- 不保留调试输出、临时代码、无用分支和废弃注释代码。

## 文档字符串与空行

- 普通 Python 模块顶部应声明模块级 docstring。
- `__init__.py` 只做包导出聚合时不需要模块级 docstring。
- 代码 docstring 默认使用英文。
- 模块 docstring 说明模块职责、分层边界和关键约束。
- 模块 docstring 只描述长期代码职责，不绑定 MVP、M1、M2、阶段、里程碑、迭代计划或开发流程。
- 简单模块可用一行 docstring。
- 涉及外部框架、数据库、认证、安全等边界时使用多行 docstring。
- 模块 docstring 不写作者、日期和变更历史，不重复文件名。
- 类、公共方法和公共函数必须写明确 docstring。
- 方法实现顺序为：声明行、docstring、空行、具体实现。
- 同一函数内不同处理逻辑之间使用空行分隔。
- 变量准备、校验分支、异常处理、返回构造不堆在一起。
- docstring 说明职责或行为，不复述类型注解。

## 枚举规范

- 枚举类按业务概念命名，枚举成员使用大写蛇形命名。
- 字符串枚举优先继承 `StrEnum` 并使用 `auto()` 生成值，避免手写重复字符串。
- 每个枚举成员下方应提供简短业务说明字符串，说明该值代表的业务语义。
- 如果某字段存在预定义且有限的业务取值，应优先使用枚举表达，不使用裸 `str`。

## 类型规范

- 新增代码保持 full-typed。
- 公共函数、方法、类属性和返回值必须提供类型注解。
- 能用精确类型表达时，不使用 `Any`。
- 仅类型检查需要的导入放在 `if TYPE_CHECKING:` 下。
- 泛型优先使用 Python 3.12 类型参数语法。
- 不把 `type: ignore` 作为常规手段；确需使用时标明具体原因。

## 异步与资源管理

- I/O 操作优先使用异步库。
- 异步函数中不要执行长时间阻塞调用。
- 数据库服务通过异步上下文管理器使用。
- 资源关闭放在上下文管理器或 `finally` 分支中。
- 后台任务必须有明确的错误处理策略。

## 错误处理与日志

- 不使用裸 `except`。
- 捕获异常时缩小异常类型范围。
- 只有能恢复、转换或补充上下文时才捕获异常。
- 对外错误消息不包含密钥、连接串、栈信息和内部路径。
- 自定义异常消息默认使用英文。
- 框架职责内的协议、路由、认证和集成错误，优先使用 Litestar 语义异常。
- 业务领域错误基于 `ApplicationError` 派生明确子类。
- 不使用裸 `ApplicationError` 表达具体业务错误。
- 不使用 `print` 作为运行时日志手段；命令行入口的启动失败提示除外。
- 日志消息使用参数化格式。
- 日志配置和请求日志规则遵守《日志规范》。

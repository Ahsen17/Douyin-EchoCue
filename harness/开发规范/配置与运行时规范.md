# 配置与运行时规范

本文档约束配置结构、配置加载、环境变量和应用启动边界。

## 配置入口

- 配置统一通过 `Config.get()` 读取。
- 默认配置文件名为 `config.yaml`。
- 配置文件支持 YAML、JSON、TOML。
- 新增配置结构放入 `aigc.base.config`。
- 新增配置必须挂载到 `Config`。
- 配置结构继承 `BaseStruct`。
- 日志配置通过 `Config.logging` 暴露。

## 默认值

- 默认值应支持本地最小启动。
- 路径默认值优先基于 `BASE_DIR` 和 `APP_NAME` 推导。
- 布尔、端口、超时、连接池等配置使用明确类型。
- 不使用 `None` 表达多个业务含义。

## 敏感配置

- 密钥、令牌、密码、连接串不得写入文档示例和默认配置。
- 本地配置文件不得提交到仓库，除非是明确的脱敏模板。
- 日志和异常信息不得输出完整敏感配置。
- 测试中使用明显假值，不复用真实账号或连接串。

## 环境变量

- 应用运行所需环境变量集中在启动入口或运行时适配层设置。
- 环境变量名使用大写蛇形命名。
- 不在业务逻辑中散落读取环境变量。
- 读取环境变量后应转换为明确类型，再进入配置结构。

## 运行时边界

- `create_app()` 只负责创建 Litestar 应用。
- 插件注册、路由装配、日志配置、中间件和 OpenAPI 放在 server 层。
- 路由通过 `controllers` 聚合注册。
- 插件通过 `plugins` 聚合注册。
- 请求体大小通过 `AppConfig.request_max_body_size_mb` 配置。
- 启动入口可设置运行环境，但不承载业务逻辑。
- 命令行入口允许输出启动失败提示；运行时日志不使用 `print`。
- 修改启动流程时必须确认 `app` 脚本入口仍可用。

## 插件与依赖注入

- 运行时能力扩展默认通过 `src/aigc/server/plugin` 实现，并在 `plugins` 中聚合。
- 全局依赖、认证、中间件、Store、第三方框架集成等装配属于 server plugin 职责。
- 业务 controller 不直接注册全局依赖，不直接修改应用级配置。
- 只有插件生命周期或作用域不匹配时，才使用其他注册方式，并保持入口集中。

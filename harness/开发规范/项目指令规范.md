# 项目指令规范

本文档约束开发、测试、迁移、运行和文档构建时的命令入口。

## 基本原则

- 优先使用项目封装指令，不直接调用底层工具。
- 执行陌生任务前先查看帮助信息。
- 已有 `app` 或 `make` 入口时，不绕过项目封装。
- 只有项目未封装时，才直接调用底层工具，并说明原因。

## 帮助入口

- 查看应用命令：`uv run app --help`。
- 查看子命令：`uv run app <command> --help`。
- 查看数据库命令：`uv run app database --help`。
- 查看 Make 目标：`make` 或 `make help`。
- `make --help` 只显示 GNU Make 自身帮助，不作为项目目标索引。

## 常用边界

- 数据库迁移使用 `uv run app database ...`。
- 测试和质量检查优先使用 `make test`、`make lint`、`make check`。
- 依赖同步优先使用 `make sync`。
- 文档构建优先使用 `make docs-build`。
- 应用运行优先使用 `uv run app run` 或项目约定入口。

## 禁止事项

- 不直接执行原始 Alembic 命令替代 `app database`。
- 不直接绕过 Makefile 执行已封装的批量质量检查。
- 不把一次性的本地命令写入文档作为长期标准。
